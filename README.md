# Digital PLS 静态 MVP

以上海Happy卓越眼科医院为演示场景。首页视觉参考用户提供的两张概念图；医院建筑图为 AI 生成的场景示意，并非医院实景。

## 使用

直接打开 `index.html` 即可查看。将本文件夹的全部文件和子目录原样上传到 GitHub 仓库根目录，开启 GitHub Pages 的 branch/root 发布方式即可。无需构建、依赖安装或服务器。

网站进入前设有19个演示账号的登录页，统一密码由项目方指定。登录状态仅保存在当前浏览器标签页的 `sessionStorage`，关闭标签页或点击“退出”后需要重新登录。由于 GitHub Pages 是纯静态托管，账号和密码校验逻辑会随前端文件一并发布，不能替代服务器端身份认证；如需承载真实业务或患者资料，必须改为服务端认证、独立账号密码及权限审计。

首次在一个浏览器标签页进入网站时，会先显示面向民营眼科医院领导层的 PLS 项目介绍页；进入工作台后，同一标签页刷新不会重复显示。页面底部“项目介绍”可随时返回。库存、CEO 驾驶舱等带锚点的二级链接仍可直接打开。

## MVP 范围

- 网站定位为单家医院PLS体系建设示例，不承载全国42家医院的名单、排名或项目数据
- 一级导航按单院落地顺序组织：项目总览、认识PLS、启动与自评、30/60/90天行动、医院流程实施、复盘与改进、知识与工具
- 项目总览增加七阶段建设路线、当前演示阶段、CEO支持事项和下一次复盘提示
- 医院流程实施以一位患者连接各部门；临床工作台、患者教育、MDT岗位能力和库存作为二级工作台保留
- 角色选择、首页工作台、九段患者旅程
- 新增面向CEO及中文读者的“认识PLS”一级页面：解释 Premium、Lens、Surgery 三个字母，说明PLS并非新术式或高价IOL项目，并呈现两条临床路径、DLS边界、四项红线和两类核心结果
- 在 IDEAL 初评后、PLS 专项检查前设置路径确认闸门：先完成基础医学与安全判断，再结合视觉需求及知情意愿，提示标准诊疗、PLS 深度评估或医生优先复核；不自动判断医保资格或手术适应证
- 按患者记录九个工作节点的责任岗位、交接依据与下一位接手者
- 演示患者档案、IDEAL 视觉需求记录
- 六大支柱简版自评、90 天行动任务
- 七类 MDT 岗位的知识与技能标准、五项自评和五题在线短测；全部完成后按百分制计分，80 分为演示及格线
- 工具箱现有十个独立网页的站内预览、搜索、岗位筛选与独立打开入口（`tools/`）
- “知识与工具”增加 PLS 项目决策 Q&A：完整收录 20 个问题的简明回答、管理要点、禁区与责任边界，可按岗位、类别和关键词检索；新增“县市经济水平较低是否适合开展 PLS”的分层判断
- 关键 Q&A 按工作场景嵌入分流节点、临床工作台、患者教育、视觉效果投诉、CEO 驾驶舱和首页岗位工作卡；场景入口统一跳转至完整问答，避免多处维护造成口径偏差
- 首页右下角仅显示库存速览；完整 IOL 型号/度数查询和 Catalys、VERITAS 耗材库存位于 `index.html#inventory` 二级页面，可调整演示数量
- 浏览器本地保存、JSON 导出与演示数据重置
- 首页按岗位显示患者与行动入口；运营页连接 CEO 驾驶舱及本月同批患者转化漏斗
- “运营与数据”增加未来12个月PLS经营情景测算二级页，并从CEO驾驶舱进入完整测算器；支持高端白内障与CLE/RLE、全流程营收与增量自费、三种情景、产能约束及CSV导出
- 临床页提供检查完成标记、需复核问题及规则化术前摘要预览（未接入 AI 模型）
- 医院PLS能力建设增加七类 MDT 岗位学习进度，学习三项且在线短测 ≥80 分为演示达标
- 医院PLS能力建设增加“PLS三级能力认证”二级页，展示基础实践认证、卓越实践认证、卓越示范中心、八大评估模块、现场核查、年度复评与红线；演示数据不会自动授予认证
- 患者教育二级页按阶段展示讲解主题，并记录当前演示患者的讲解进度
- 首页患者教育入口与二级互动体验：白内障、老花、单焦点、双焦点、EDOF、FVR 和 Toric 的视觉示意；日间/夜间场景；Phaco 与 FLACS 的分步解释；光晕眩光及视觉效果投诉的咨询师回应流程
- 进入主页前的 PLS 项目介绍页：患者需求变化、医院/医生/患者价值、质量闭环、术前术中术后路径、强生眼力健共建支持及 90 天试运行路线

所有初始患者、指标、IOL 规格和库存数量均为虚构演示数据。数据只保存在当前浏览器的 `localStorage`，不会跨设备同步。库存查询不会预留或扣减库存，也不与医院库存系统连接；IOL 规格需由医生确认。请勿录入真实患者个人信息。岗位选择不验证身份，交接记录不能作为临床签名。自评和五题短测仅用于 MVP 展示，不构成医院正式上岗认证。`tools/` 下的页面是原工具网页的独立副本，其表单、打印、评分等逻辑不会同步到本 MVP 的患者档案；其中部分工具可能另行使用浏览器本地存储。临床页面不提供自动诊断或人工晶体推荐。决策 Q&A 是项目建设和团队沟通参考，不替代医生诊疗判断，也不替代属地医保、收费、财税、合规和对外传播审核。

视觉模拟和手术图解是艺术化教学示意，不能预测个人术后效果，也不用于比较具体产品疗效。光晕眩光及投诉回应为示范流程，危险症状必须优先转医生；咨询师不能独立诊断、用药或承诺恢复结果。正式上线前需要医院确认品牌素材使用、临床内容、产品资料与患者教育材料，建设身份权限、审计、数据存储、备份及医院系统集成。公开 GitHub Pages 不适合承载真实患者数据。
